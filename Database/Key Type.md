## คีย์ (Key) แต่ละประเภท

### 1. Unique Key (คีย์ข้อมูลห้ามซ้ำ)

* **ทำงานอย่างไร:** หน้าที่ของมันคือบังคับไม่ให้ข้อมูลในคอลัมน์นั้นซ้ำกันเลย เช่น อีเมลผู้ใช้งาน หรือ เบอร์โทรศัพท์
* **ส่งผลกับ Page Split ไหม?:** **ส่งผลแน่นอนครับ**
* **เพราะอะไร:** เบื้องหลังการทำงาน เมื่อคุณสร้าง Unique Key ระบบ Database จะ "แอบสร้างหน้าสารบัญ (Index)" ให้คอลัมน์นี้อัตโนมัติ เพื่อให้มันตรวจเช็คของซ้ำได้ไวๆ
* **Usecase:** สมมติคุณเก็บอีเมลลูกค้า วันหนึ่งมีลูกค้าชื่อ `a... @email.com` สมัครเข้ามา ระบบต้องเอาอีเมลนี้ไปแทรกในหน้าสารบัญหมวดตัว A หากหน้าสารบัญหมวดตัว A เต็มพอดี ก็จะเกิด Page Split (การแยกหน้า) ที่หน้าสารบัญครับ

### 2. Composite Key (คีย์ผสม)

* **ทำงานอย่างไร:** คือการเอาคอลัมน์ตั้งแต่ 2 คอลัมน์ขึ้นไปมารวมร่างกันเพื่อทำหน้าที่เป็น Primary Key หรือ Unique Key เช่น การรวม **"รหัสสาขา + เลขที่ใบเสร็จ"**
* **ส่งผลกับ Page Split ไหม?:** **ส่งผลครับ แต่จะมากหรือน้อยขึ้นอยู่กับ "คอลัมน์แรก" เป็นหลัก**
* **เพราะอะไร:** การจัดเรียงข้อมูลของคีย์ผสม จะยึดการเรียงตามคอลัมน์แรกก่อนเสมอ ถ้าคอลัมน์แรกซ้ำกัน ถึงจะไปเรียงตามคอลัมน์ที่สอง
* **Usecase:**
* *กรณีรอดตัว (ไม่ค่อย Split):* ถ้าคีย์ผสมของคุณเอา "วันที่" ขึ้นก่อน เช่น "20231015 + รหัสลูกค้า" ข้อมูลใหม่ของวันนี้ก็จะถูกนำไปต่อท้ายสมุดเสมอ แบบนี้ปลอดภัย
* *กรณีเกิด Split:* ถ้าคีย์ผสมเอา "รหัสลูกค้า" ขึ้นก่อน เช่น "รหัสลูกค้า + วันที่" เวลามีลูกค้าเก่า (ที่รหัสอยู่หน้าแรกๆ) มาซื้อของใหม่ ข้อมูลบิลใหม่ของเขาจะต้องวิ่งไปแทรกตรงกลางหน้าแรกๆ เสมอ ถ้าหน้าแรกเต็มก็... ตู้ม! เกิด Page Split ทันทีครับ

### 3. Foreign Key (คีย์นอก หรือ คีย์อ้างอิง)

* **ทำงานอย่างไร:** ตัวมันเองมีหน้าที่แค่ "เป็นยามตรวจเช็ค" ว่าข้อมูลที่คุณกำลังใส่ลงมา มีอยู่จริงในอีกตารางหนึ่งหรือไม่ (เช่น จะเพิ่มบิลของลูกค้ารหัส 001 ยามก็จะไปเช็คว่ามีลูกค้า 001 อยู่ในระบบจริงๆ ไหม)
* **ส่งผลกับ Page Split ไหม?:** **โดยตัวมันเอง "ไม่ส่งผล" ครับ แต่สิ่งที่มาคู่กับมันต่างหากที่ส่งผล**
* **เพราะอะไร:** การมีแค่ Foreign Key ไม่ได้ทำให้ข้อมูลถูกจัดเรียงใหม่ **แต่ในชีวิตจริงของการทำ Database** การที่ตารางสองตารางผูกกัน ระบบต้องมีการดึงข้อมูลข้ามไปมาบ่อยมาก DB Admin จึงมักจะ "สร้าง Index (สารบัญ)" ให้กับคอลัมน์ที่เป็น Foreign Key ด้วยเสมอ
* **Usecase:** พอเราสร้าง Index ให้มันปุ๊บ มันก็จะกลับไปเข้าอีหรอบเดียวกับ Unique Key เลยครับ คือถ้าข้อมูล Foreign Key ที่ใส่เข้ามาเป็นเลขแบบสุ่ม ไม่ได้เรียงลำดับ "หน้าสารบัญของ Foreign Key" ก็จะเกิด Page Split ได้เช่นกัน
