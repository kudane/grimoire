#  I N D E X

Index (ดัชนี) สารบัญหนังสือ ตัวช่วยค้นหาข้อมูลเจอได้ไวขึ้นป

> Index หลักๆ มี 2 ประเภท คือ Clustered Index และ Non-Clustered Index

<br>

## Clustered Index (ดัชนีแบบจัดเรียงข้อมูลจริง)
ข้อมูลในตารางจะถูกเรียงลำดับทางกายภาพ (Physical) ตามคอลัมน์ที่เราทำ Clustered Index และ 1 ตาราง (Table) จะมี Clustered Index ได้แค่ 1 ตัวเท่านั้น โดยปกติ เมื่อเราสร้าง Primary Key (คีย์หลักของตาราง) ระบบจะสร้าง Clustered Index ให้คอลัมน์นั้นอัตโนมัติ

<br>

## Non-Clustered Index (ดัชนีแบบชี้เป้า)
โครงสร้างข้อมูลที่ถูกสร้างแยกออกมาต่างหากจากข้อมูลจริง เก็บแค่ **ค่าของคอลัมน์ที่เราทำ Index** คู่กับ **ตัวชี้เป้า (Pointer หรือ Bookmark)** ว่าข้อมูลเต็มๆ บรรทัดนี้ อยู่ที่ไหนในตารางจริง และ 1 ตาราง สามารถมี Non-Clustered Index ได้หลายตัว

<br>

## Usecase จริง: การออกแบบ 1 Table

สมมติเราต้องออกแบบตารางเก็บข้อมูลการสั่งซื้อสินค้า **`Orders`** ในระบบ E-Commerce

**โครงสร้างตาราง:**

* `OrderID` (รหัสใบสั่งซื้อ - เป็นตัวเลขรันอัตโนมัติ)
* `CustomerID` (รหัสลูกค้า)
* `OrderDate` (วันที่สั่งซื้อ)
* `TotalAmount` (ยอดเงินรวม)

**การออกแบบ Index ที่เหมาะสม:**

1. **Clustered Index:**
* **เลือกใช้กับ:** `OrderID` (ตั้งเป็น Primary Key)
* **เหตุผล:** เป็นตัวเลขที่รันไปข้างหน้าเรื่อยๆ ข้อมูลใหม่จะถูกเขียนต่อท้ายเสมอ ไม่เกิดปัญหา Page Split และบ่อยครั้งที่ระบบต้องดึงข้อมูลใบสั่งซื้อตาม ID นี้ตรงๆ


2. **Non-Clustered Index (ตัวที่ 1):**
* **เลือกใช้กับ:** `CustomerID`
* **เหตุผล:** ผู้ใช้มักจะเปิดดูประวัติการสั่งซื้อของตัวเอง (เช่น ค้นหาว่าลูกค้ารหัส A001 ซื้ออะไรไปบ้าง) การมีดัชนีชี้เป้าที่รหัสลูกค้า จะช่วยให้หาใบสั่งซื้อของลูกค้ารายนี้เจอทันที โดยไม่ต้องสแกนหาทั้งตาราง


3. **Non-Clustered Index (ตัวที่ 2):**
* **เลือกใช้กับ:** `OrderDate`
* **เหตุผล:** ทีมบัญชีหรือการตลาดมักจะดึงรายงานสรุปยอดขาย "ตามช่วงเวลา" (เช่น ดึงออเดอร์ของเดือนที่แล้ว) ดัชนีตัวนี้จะช่วยให้กวาดข้อมูลตามวันที่ได้รวดเร็ว
