# Database Indexing 101: สารบัญค้นหาข้อมูลฉบับเข้าใจง่าย

เปรียบเสมือน **สารบัญหนังสือ** ที่ช่วยให้ระบบฐานข้อมูลค้นหาเรคอร์ดที่ต้องการได้ทันที โดยไม่ต้องเปิดอ่านทีละหน้าจนจบเล่ม

> **คีย์เวิร์ดสำคัญ:** Index หลักในฐานข้อมูลมี **2 ประเภท** ได้แก่ `Clustered Index` และ `Non-Clustered Index`

---

## 1. Clustered Index (ดัชนีจัดเรียงข้อมูลจริง)

* **การจัดเก็บ:** จัดเรียงข้อมูลทางกายภาพ (`Physical`) ในตารางจริงตามคอลัมน์ที่กำหนด
* **ข้อจำกัด:** กำหนดได้เพียง **1 ตัว ต่อ 1 ตาราง (`Table`)**
* **ค่าเริ่มต้น:** ระบบจะสร้างให้อัตโนมัติทันทีเมื่อกำหนด `Primary Key`

---

## 2. Non-Clustered Index (ดัชนีชี้เป้า)

* **การจัดเก็บ:** แยกโครงสร้างออกมาต่างหาก ไม่แตะต้องลำดับข้อมูลจริงในตาราง
* **รูปแบบการทำงาน:** เก็บ **ค่าของคอลัมน์** คู่กับ **ตัวชี้พิกัด (`Pointer` หรือ `Bookmark`)** เพื่อบอกตำแหน่งจริงของข้อมูล
* **ข้อจำกัด:** สร้างได้ **หลายตัว ต่อ 1 ตาราง** ตามรูปแบบคำสั่งค้นหาที่ใช้งานบ่อย

---

## 3. กรณีศึกษา: การออกแบบ Index สำหรับตาราง `Orders`

สมมติต้องออกแบบโครงสร้างตารางระบบ `E-Commerce` โดยมีคอลัมน์ดังนี้:

* `OrderID` — รหัสใบสั่งซื้อ (ตัวเลขรันอัตโนมัติ)
* `CustomerID` — รหัสลูกค้า
* `OrderDate` — วันที่สั่งซื้อ
* `TotalAmount` — ยอดเงินรวม

### แนวทางการวาง Index ที่มีประสิทธิภาพ

1. **`OrderID` $\rightarrow$ ทำ `Clustered Index` (ตั้งเป็น `Primary Key`)**
* **เหตุผล:** เป็นตัวเลขเรียงลำดับ ข้อมูลใหม่จะถูกเขียนต่อท้ายเสมอ ป้องกันปัญหา `Page Split` และรองรับการดึงข้อมูลตามรหัสใบสั่งซื้อโดยตรงได้เร็วที่สุด


2. **`CustomerID` $\rightarrow$ ทำ `Non-Clustered Index**`
* **เหตุผล:** รองรับกรณีลูกค้าเรียกดูประวัติคำสั่งซื้อของตนเอง ระบบจะกระโดดไปหาข้อมูลตามรหัสลูกค้าได้ทันทีโดยไม่ต้องสแกนหาทั้งตาราง (`Full Table Scan`)


3. **`OrderDate` $\rightarrow$ ทำ `Non-Clustered Index**`
* **เหตุผล:** รองรับการดึงรายงานสรุปยอดขายตามช่วงเวลาของฝ่ายบัญชีหรือการตลาด ช่วยให้กรองข้อมูลตามช่วงวันที่ได้อย่างรวดเร็ว
