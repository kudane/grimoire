#  P A G E &nbsp;&nbsp;&nbsp; S P L I T

ระบบฐานข้อมูล จะเก็บข้อมูลลงในหน่วยย่อยที่สุดที่เรียกว่า "Page" (เปรียบเสมือน "กล่อง" เก็บเอกสารที่มีขนาดคงที่ เช่น กล่องละ 8KB) เมื่อเราสร้าง Index ข้อมูลในกล่องเหล่านี้จะถูกจัดเรียงตามลำดับอย่างเป็นระเบียบ

> Page Split จะเกิดขึ้นเมื่อ "กล่องใบหนึ่งเต็มแล้ว" แต่เรามีความจำเป็นต้องแทรกข้อมูลใหม่เข้าไปตรงกลางกล่องใบนั้นพอดี หรือ ข้อมูลเดิมถูกแก้ไขให้มีขนาดใหญ่ขึ้น

## นัยสำคัญ
- Primary Key (คีย์หลัก) คือรหัสที่ใช้ระบุตัวตนของข้อมูลแต่ละแถวแบบไม่ซ้ำกัน ตัวเลขรันอัตโนมัติ (เช่น 1, 2, 3...) แทบไม่เกิด Page Split เลย ระบบทำงานได้เร็วและลื่นไหล

## แนวคิด
- UUID เป็น Primary Key ถึงทำให้เกิด Page Split มหาศาล
- Page จะถูกเรียงลำดับตาม "Index Key" หรือที่เจอบ่อยที่สุดก็คือ Primary Key
- Page Split บ่อย ก่อให้เกิดข้อมูลกระจัดกระจายในฮาร์ดดิสก์ (Fragmentation)
- Fill Factor ใช้เป็นวิธีแก้ปัญหาเชิงป้องกัน
- Index Rebuild ไม้ตายสุดท้าย
